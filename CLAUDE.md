# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal notes and to-do app, similar to Obsidian: Tauri 2 (Rust) + Vite + React 19 + React Router v7 (data mode, SPA) + CodeMirror 6 + SQLite (rusqlite) + Tailwind v4. **Phase 1: macOS only, local only, no sync.** Later phases add Windows, Linux, Android, a web build and a self-hosted sync server, so keep changes portable. Don't implement sync, auth or a server unless asked.

`ARCHITECTURE.md` is the detailed reference: data model, how each feature works, and what each future phase needs. Read it before any non-trivial change.

## Commands

Node comes from nvm (`.nvmrc` = 24). Non-interactive shells need it sourced first:
`export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; nvm use --lts`

```sh
pnpm tauri dev                 # run the app (Vite on fixed port 1420 + Rust shell)
pnpm build                     # tsc --noEmit + vite build
pnpm typecheck
pnpm test                      # Vitest, all files
pnpm test src/lib/date.test.ts # one test file
pnpm test -t "monthGrid"       # tests matching a name
cargo test                     # all Rust tests (workspace)
cargo test -p vault-core tasks::parser          # one module
cargo test -p vault-core done_at_is_set         # tests matching a name
pnpm bindings                  # regenerate src/bindings/*.ts from Rust model types (commit the output)
pnpm tauri build               # release .app/.dmg
```

There is no linter or formatter configured.

App data (`vault.db`, `attachments/`) lives in `~/Library/Application Support/com.gatopi.notes/`. That is the user's **real** vault. Inspect it read-only with `sqlite3`; never delete or rewrite it.

Port 1420 may already be in use by the user's own `pnpm tauri dev`. Before a smoke run, check with `lsof -nP -iTCP:1420 -sTCP:LISTEN`. When stopping processes, kill only the PIDs you started; don't use broad `pkill -f vite`.

## Architecture (big picture)

Three layers, with strict boundaries:

1. **`crates/vault-core/`**: all business logic and storage. It must not depend on Tauri, because it will be reused on Android and by a sync server. Everything goes through the `Vault` struct (`lib.rs`), and each module adds methods with `impl Vault { … }`.
2. **`src-tauri/`**: a thin command layer. Each command is `#[tauri::command(async)]` and just calls `with_vault(state, |v| v.method(..))`. The vault is a single `Mutex<Vault>`. CPU-heavy work, such as image processing, runs **before** taking the lock.
3. **`src/`** (React): talks to the backend **only** through `src/api.ts`, which defines the `Api` interface and the Tauri implementation. Nothing else may import `@tauri-apps/*`. The web build will replace this module. No SQL in the frontend.

### Rules every write in `vault-core` follows
- One write = one transaction. Every change to a syncable row also calls `changes::log(tx, entity, id, op, now)` **in that same transaction**.
- Deletes are soft: set `deleted_at` and `updated_at`. All reads filter `deleted_at IS NULL`.
- IDs are UUIDv7, generated by the client (`src/lib/id.ts`, attached inside `api.ts`) and validated with `ids::check`. Never use autoincrement IDs for synced data. Soft-deleted IDs are never reused.
- Timestamps are Unix milliseconds (`time::now_ms`). Daily-note dates are local `YYYY-MM-DD` strings; "today" is computed in the frontend.
- Shared insert logic is a `pub(crate) fn insert(conn: &Connection, …)` so other modules can call it inside their own transaction (e.g. `daily.rs` uses `folders::insert` / `notes::insert`).
- `notes::save_note_body` is the single save pipeline: update body → log the change → `tasks::reindex_note`. FTS is updated by SQL triggers. Anything that changes a body, including toggling a task, must go through it.
- Derived tables (`tasks`, `notes_fts`) are rebuilt locally and are never synced.

### Migrations
`crates/vault-core/src/db/migrations.rs` keeps an ordered list of `Migration { sql, after }`, tracked with `PRAGMA user_version`. To add one, create `db/sql/000N_*.sql` and append an entry; `after` is an optional Rust backfill step that runs inside the migration's transaction. **Never edit a migration that has already run.**

### Adding a feature end to end
1. Core method on `Vault`, with tests. New model types go in `model.rs` with `#[cfg_attr(feature = "ts", derive(ts_rs::TS), ts(export))]`, and `#[ts(type = "number")]` on `i64` fields.
2. Command in `src-tauri/src/commands/<area>.rs`, registered in `generate_handler!` in `src-tauri/src/lib.rs`. Add capabilities in `src-tauri/capabilities/default.json` if it needs a plugin.
3. `pnpm bindings`.
4. Add the method to the `Api` interface and `tauriApi` in `src/api.ts`.
5. Use it from a route loader or action.

### Frontend patterns
- Routes are declared in `src/router.tsx`. Route modules export `loader` / `action` / `Component`. The root loader provides `{ folders, notes }` (summaries without bodies), read via `useRouteLoaderData("root")`.
- Structural changes go through the `/tree` resource action (`routes/tree-action.ts`, a typed `TreeIntent` sent as JSON, via `useTreeAction()`). Errors show as toasts. Actions revalidate all loaders.
- Autosave deliberately bypasses actions: `components/NoteEditor.tsx` debounces calls to `api.saveNoteBody` and flushes them on unmount, window blur and `api.onBeforeClose`. Note loaders call `waitForPendingSaves()` first.
- `NoteEditor` / `Editor` must be keyed by note id. The editor owns the document after mount and reads callbacks through a ref.
- Editor extensions live in `src/editor/`. `[[links]]` are a Lezer syntax node (`markdown.ts`), and checkboxes use the GFM `TaskMarker` node, so neither triggers inside code. Image block widgets must come from a `StateField` (not a ViewPlugin).
- Pure logic goes in `src/lib/` with `*.test.ts` alongside. TypeScript is strict with `noUncheckedIndexedAccess`.

### Gotchas
- The task parser uses `pulldown-cmark` so code blocks and nested lists are handled correctly; don't replace it with line regexes. Task id = `<note_id>:<line_hash>`, where the hash covers the normalized text plus its occurrence index (not the checkbox state or line number).
- `notes_fts` is a regular FTS5 table keyed by `note_id`. It is intentionally not external-content: implicit rowids on `notes` can change on VACUUM. User queries go through `search::fts_query`, which quotes every word.
- Images: `![](att:<sha256>)`, stored as `attachments/<hash>.webp` and displayed via `api.attachmentUrl` (`convertFileSrc`, with the asset protocol scoped to `$APPDATA/attachments/**`). Pasted bytes are sent as raw binary IPC with an `x-filename` header.
- `dragDropEnabled` is `false` in `tauri.conf.json`: the sidebar and image drops rely on HTML5 drag-and-drop.
- In dev, dependencies are compiled with `opt-level = 2` (root `Cargo.toml`) so image processing is fast. The first build is slow.
